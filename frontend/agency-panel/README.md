# پنل آژانس (Agency Panel)

پنل مخصوص حساب‌های نقش AGENCY — شرکای B2B پلتفرم «مراقب من». طبق سند
معماری، یک آژانس می‌تواند یک شرکت تأمین‌کننده مراقب (با استخر مراقبان
خودش)، یک مشتری سازمانی که کارمندانش (خانواده‌ها) از خدمت استفاده
می‌کنند، یا هر دو باشد.

## اجرا

```bash
npm install
cp .env.local.example .env.local   # در صورت نیاز آدرس بک‌اند را تغییر دهید
npm run dev
```

بک‌اند (Django) باید همزمان روی `http://localhost:8000` در حال اجرا باشد.

## معماری فاز ۱ (فعلی)

این فاز فقط پایه را می‌سازد — طبق نقشه راه، گزارش‌گیری HR-style و
داشبورد تحلیلی عمیق‌تر در فازهای بعدی (`apps.finance`، `apps.analytics`)
روی همین دو جدول ارتباطی ساخته می‌شوند:

- **ورود** → **داشبورد** (اطلاعات شرکت، کد عضویت، شمارش سریع خانواده‌ها
  و مراقبان)
- **خانواده‌های زیرمجموعه** (`/families`) — لیست عضوها + درخواست‌های در
  انتظار تأیید
- **استخر مراقبان** (`/caregivers`) — لیست مراقبان زیرمجموعه + درخواست‌های
  در انتظار تأیید

خانواده یا مراقبی که می‌خواهد به این آژانس بپیوندد، این کار را از پنل
خودش (family-panel / caregiver-panel) با وارد کردن کد عضویت آژانس
(`AGN-XXXXXX`) انجام می‌دهد — درخواست همیشه با وضعیت "در انتظار تأیید"
ثبت می‌شود و این آژانس است که باید تصمیم بگیرد؛ برخلاف بعضی جریان‌های
مشابه در پلتفرم (مثل کد بیمار)، اینجا هیچ طرفی از قبل اختیار تأیید خودکار
ندارد.

## نکته مهم

پیوستن یک مراقب به استخر یک آژانس، یک ارتباط جداست از فرآیند تأیید اصلی
مراقب در پلتفرم (`CaregiverProfile.status` — همچنان فقط توسط ناظر/ادمین
پلتفرم تغییر می‌کند). یک مراقب می‌تواند حتی پیش از تأیید نهایی پلتفرم،
درخواست پیوستن به آژانس بدهد.
